IDEA TITLE — PARAKH: the prescriptive layer on PAIMANA
PAIMANA already tells MoSPI what happened. PARAKH tells it what is about to change, why, and what to do about it — on the same monthly data.
PROPOSED SOLUTION — DETAILED EXPLANATION
The brief's own conclusion: monitoring must move from descriptive reporting to predictive and prescriptive decision support. PARAKH is that layer — it reads the monthly CUF/PAIMANA update ministries already file and turns it into a ranked, explained, actionable review queue.
It asks for no new form, no new portal and no new field entry from any project administrator.

HOW IT ADDRESSES THE PROBLEM
The brief's diagnosis — cost overruns, time overruns and implementation risks become visible only after they are reported, so intervention is always late.
PARAKH answers the three questions a monitoring cell needs, for every project, every month:
• WHAT WILL CHANGE? whether the cost will be revised upward, or the completion date will move, at the next monthly report.
• WHY? the inputs that pushed that ranking up or pulled it down, for that project.
• WHAT NEXT? an action class for the reviewer, the peer benchmark behind it, and the role that owns it.
Because the queue is sized to staff capacity, it prioritises interventions instead of describing them.
Unverified data never scores — a record that fails reconciliation is held for review, not silently predicted on.
INNOVATION AND UNIQUENESS OF THE SOLUTION
1 · Prescriptive, not just predictive. Every alert carries a recommended action class, the peer benchmark that justifies it, and the owner role.
2 · We predict drift, not failure. A project rarely collapses; its clocks separate. Measuring the gap below makes the warning explainable in one sentence.
3 · Two engines, never blended. Conventional statistics and machine learning are scored on identical folds and reported side by side, so the department sees where ML earns its place.
4 · An evidence gate on every score. Validation status travels with every prediction, and every figure keeps its source page.
5 · It measures itself. Reviewer dispositions are recorded, so accuracy claims become a measured precision@K instead of a promise.
THE THREE CLOCKS · WHY A PROJECT SLIPS MONTHS BEFORE THE REPORT SAYS SO
TIME vs PROGRESS
share of the approved timeline consumed against share of physical work completed
MONEY vs PROGRESS
share of the revised cost released against share of physical work completed — paying ahead of building
PROMISE vs RECORD
how many times the cost or the completion date have already been revised — repetition predicts repetition
PARAKH ranks by the widest gap between the three clocks — not by the loudest number, and not by a black-box score.

TECHNOLOGIES TO BE USED
Ingestion and evidence
Python · pandas · Parquet · pdfplumber. Every value keeps its report and page; unverified records are held, not scored.
Modelling and attribution
scikit-learn (logistic regression, gradient boosting) · XGBoost · statsmodels for the conventional statistical baseline · SHAP for exact per-project attributions.
Prescriptive and language layer
A rule-based prescription playbook over computed evidence, plus an open-weight LLM running locally (Llama / Mistral class, via Ollama) for the project-intelligence assistant — it narrates evidence, it never invents numbers.
Serving and deployment
Next.js (React) dashboard + REST API · Docker · single node, CPU only, no paid model API.
(a) PREDICTIVE MODELS THE BRIEF ASKS FOR
Cost-escalation model · schedule-delay model · composite project risk score
Horizon: the next monthly report (T+1). Output: a ranking with a risk band and the drivers behind it — never a bare number.

Verdict:
ML wins where events are frequent — completion dates moved in 18.1% of project-months and the ML ranking lifts precision 2.2× over the base rate. Where events are rare the simpler model generalises better, so on cost revisions we ship logistic regression. We ship what the strict holdout selects, not the fashionable choice.
(c) IS THE SIGNAL IN TODAY'S CUF FIELDS, OR IN FIELDS NOT YET CAPTURED?
Inside the CUF the strongest signals are already trajectories, not levels: timeline used so far 36%, the agency's own overrun record 23%, delay reported so far 10%, spend ahead of work 6% (mean |SHAP| share, schedule model) — so the current CUF genuinely carries early-warning signal.
The planned ablation answers the second half: train CUF-only, then add non-CUF context one block at a time — land acquisition, monsoon and rainfall, commodity indices, DPR quality — and publish the marginal lift of each block. That tells MoSPI which new field is worth collecting, and what it buys.

ANALYSIS OF THE FEASIBILITY OF THE IDEA
TECHNICAL
Open-source stack, CPU-only, one batch run per month. The ingestion path is already exercised on 17 published reports (2,522 pages) with 0 failed extractions.
ECONOMIC
No licence fee, no paid model API, no GPU. The marginal cost of one more month is a single batch job on one internal server.
OPERATIONAL
It rides the monthly rhythm MoSPI already runs: ministries file the CUF, PAIMANA updates through role-based access and APIs, PARAKH consumes the update and the queue is ready for the review cycle. Analysts keep PAIMANA.
DATA AND GOVERNANCE
Built on current CUF fields. Reconciliation is real: 11 of the 13 current-format reports match their own printed totals exactly — project count and all three financial totals — and legacy gaps are disclosed, not hidden.
PILOT PATH — WITH MoSPI, ON PUBLISHED DATA, NO NEW COLLECTION
Month 1: run the queue on published reports; measure precision@K against what reviewers actually open.
Month 2: calibrate scores, add non-CUF context, measure warning lead time.
Month 3+: extend into the OCMS archive, then hand over a documented deployment.

BENEFITS OF THE SOLUTION (SOCIAL · ECONOMIC · ENVIRONMENTAL)
ECONOMIC — bringing one cost or time revision one monthly cycle earlier on a ₹42.78 lakh crore portfolio is material, and needs no new data-collection budget.
ADMINISTRATIVE — review effort becomes proportionate to risk across 1,981 ongoing projects instead of uniform across all of them.
ACCOUNTABILITY — “Why was this flagged?” is answered from a source-linked trail in seconds: report, page, changed field, drivers.
ENVIRONMENTAL — earlier action on stalled civil works cuts re-mobilisation, idle machinery and rework, where a delayed project's emissions sit.
REUSABLE — document-driven by design, so the same engine serves the 22 sectors here and any state portfolio that publishes monthly reports.
PILOT SCORECARD — TO BE MEASURED WITH MoSPI
